# Speaker calibration in Settings → People

Choose **All finished notes** or a date range, set the note and reviewed-row budgets, and select **Run calibration**. The job reads owner-reviewed speaker labels already in saved meeting transcripts. It runs behind the renderer, shows progress, rows re-embedded and bytes read, and can be cancelled. No export or import is needed. Applying the report is a separate action, recorded in the ordered People action history. Undo restores the preceding values and per-threshold statuses without changing transcript corrections.

The report contains one **diagnostic threshold sweep**. It compares stored cluster centroids with current profiles, using a new embedding from retained row audio when a stored centroid is missing. Conflicting reviewed cluster labels are excluded. Expired, evicted, absent or partial audio is excluded with a reason. The report counts stored and reconstructed evidence separately, but computes only one sweep. This reconstructed comparison does not replay production decisions. The former live-estimate table used the same vectors and has been removed.

Version 3 reports have a distinct result type:

- `diagnostic_only`: measured diagnostics, named failed admission criteria, a next action, and an empty `recommended` object. The UI shows no recommendation panel, winner summary or Apply action. Reviewed labels and manual settings remain available.
- `supported_recommendation`: selected threshold values in `recommended`, the admission `policy`, `evidenceScope`, `validation` summary and `uncertainty`. Only this type can be applied as a new calibration.

The existing minimums remain: 30 reviewed rows across three notes and two people, two current profiles, ten machine claims, twelve consistent diagnostic examples, and valid audio/model/profile fingerprints. Admission also requires production decision observations at the frozen selected thresholds and matching model/profile fingerprints, with an independent holdout whose recording sessions are disjoint from every tuning session. Splitting rows or notes from the same recording session does not qualify. Holdout examples must include enrolled people (positive coverage) and unenrolled or unknown people (negative coverage). Both the tuning winner and holdout must accept names; universal refusal can never qualify. Correct-name coverage is correct accepted names divided by positive examples; precision is correct accepted names divided by all accepted names, including incorrect names on negative examples.

All minimums live in `src/helpers/speakerCalibrationPolicy.js`. The owner must predeclare `minimumCorrectNameCoverage` and `minimumPrecision`; both are deliberately `null` until set. Numeric targets in test fixtures are illustrative only. The current job reconstructs vectors and cannot supply independent production observations or verified recording-session identities. It therefore returns diagnostics, even if its sweep appears perfect. Future evidence acquisition is outside this slice; a trusted independent holdout fixture exercises the supported branch without adding an evidence-snapshot schema or changing recognition.

Reports are tied to current row revisions, recordings and profile embeddings; changes require a new run. Reconstructed vectors are never saved to a profile, exemplar, or note embedding table. Per-note messages preserve the actual completion cause: skipped or failed diarization, failed extraction, rejected persistence, key mismatch, missing completion event, unavailable model/audio, or unknown. Display derives from `vectorsWritten`, `clusters`, and `cause`; the stored meaning of `had_speaker_embeddings` is unchanged. Default-zero migrated counters without a recorded cause are ambiguous and display as **not recorded**. No database migration is added.

New reports require admission at application and settings reload. Legacy applied settings retain their existing values and runtime status because changing that status would change the production naming floor. There is no settings or storage migration in this slice. The existing fixed automatic-naming floor of 0.60 and all recognition rules and defaults are unchanged.

**No recommendation is made for `minimumVoicedSeconds` or `overlapToleranceSeconds` from history.** The production voiced-seconds gate used the matched diarization turn's duration, which was not stored. The stored overlap flag is only an outcome at one tolerance. The original matched turns and overlap intervals, or an exact way to rederive them, are needed to sweep those parameters. Both remain visibly uncalibrated.

The older `npm run calibrate -- --meeting <exported-folder>` tool remains for explicit offline experiments. Its rows are compared with leave-one-row-out centroids made from the owner's labels in that export. That uses a different profile set and method from the in-app comparison above. Its version 1 reports leave `recommended` empty and cannot mark in-app thresholds calibrated.
